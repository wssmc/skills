````markdown
# 论文写作技巧总结

本文件总结了本次会话中关于车间调度论文写作形成的主要技巧，适用于 hybrid flow shop scheduling、due-window-based weighted earliness/tardiness、high-priority jobs、machine-unavailability periods、non-preemptive operations、MIP 对比实验和摘要写作等内容。

---

## 1. Related Work 写作技巧

Related Work 不宜写成“文献堆砌”，而应围绕论文问题的核心要素组织。对于本文问题，推荐逻辑为：

```text
车间类型 → 目标函数 → 特殊作业/优先级 → 机器不可用/非抢占 → 研究空白
````

较合适的小节结构包括：

```latex
Hybrid flow shop scheduling and due-date-related objectives
Due-window-based total weighted earliness and tardiness scheduling
Priority differentiation and high-priority job scheduling
Machine unavailability and non-preemptive operations
Research gaps and positioning of this study
```

最后的 `Research gaps and positioning` 不应重新综述文献，也不应再次集中引用前文已经出现过的文献。前面小节已经承担了文献归类和引用功能，最后一节应主要完成三件事：

```text
承接前文 → 概括 gap → 定位本文贡献
```

推荐写法：

```latex
The preceding subsections show that the main components of the present problem
have been studied in different scheduling contexts. However, these features
have mainly been considered in partial combinations rather than within a unified
HFSP framework.
```

---

## 2. 文献引用技巧

不要为了“显得有依据”而重复引用。一个 citation 如果已经在前文用于支撑某个研究方向，后文 gap 部分就不必再次系统性罗列。

更好的写法是：

```latex
Existing studies have mainly considered these features in partial combinations.
```

而不是：

```latex
Existing studies on HFSP ..., due windows ..., priority ..., and machine
availability ... have shown that ...
```

建议：

* 2.1–2.4 负责文献分类、引用和发展脉络。
* 2.5 负责归纳研究空白和定位本文。
* 2.5 中正文可以不再出现大量 citation。
* Gap summary table 可以承担文献对比功能。

---

## 3. Research Gap 表述技巧

Gap 不能只写“previous studies have not considered...”，而应说明为什么这些要素组合后会产生新的调度难点。

推荐逻辑：

```text
job-level weights 只能表达个体重要性；
但高优先级作业可能来自同一紧急订单或协同交付任务；
因此多个高优先级作业可能需要共享 due windows；
同时机器不可用和非抢占处理会影响可行性判断；
这些因素在 HFSP due-window TWET 框架中尚未被充分集成。
```

推荐表述：

```latex
Existing studies usually represent priority differentiation through job-level
weights and thus treat job importance as an individual-job attribute. However,
high-priority jobs may also arise from urgent orders or coordinated delivery
tasks, where multiple jobs need to be protected jointly through shared due
windows.
```

---

## 4. Abstract 写作技巧

摘要应遵循清晰链条：

```text
背景 → 问题定义 → 关键约束 → 文献缺口 → 方法 → 核心机制 → 实验 → 结果 → 实际意义
```

摘要开头不要反复列举同一组问题要素。例如，已经出现：

```latex
high-priority jobs, due windows, machine-unavailability periods
```

后面就不要再重复写：

```latex
differentiated delivery priorities, time-window requirements, and
machine-availability restrictions
```

更好的处理是先定义问题，再解释难点：

```latex
This study examines a hybrid flow shop scheduling problem with high-priority
jobs, due windows, and machine-unavailability periods (HFSPDW-HPJMUP).
Operations are non-preemptive and must be processed entirely within available
machine intervals. These coupled constraints complicate both feasibility
checking and schedule optimization.
```

## 5. 缩写命名技巧

缩写不宜过长。`HFSPDW-HPJMUP` 已经比较长，不建议再加入 `NPO` 表示 non-preemptive operations。

推荐写法：

```latex
This study examines a hybrid flow shop scheduling problem with high-priority
jobs, due windows, and machine-unavailability periods (HFSPDW-HPJMUP).
Operations are non-preemptive and must be processed entirely within available
machine intervals.
```

也就是说：

```text
缩写覆盖主要问题结构；
其他关键假设单独说明。
```

## 6. MIP 对比写作技巧

如果 MIP 是 600 秒限时求解，不能把 MIP 结果称为 “optimal solution”，除非 solver 明确报告 optimal 或 gap 为 0。

应使用：

```text
time-limited MIP reference
time-limited MIP incumbent
best recorded objective value
best observed solution
```

不要使用：

```text
MIP optimum
optimal solution
the exact optimum
```

MIP 对比表中建议报告：

```text
obj    平均目标值
count  获得 best recorded objective value 的次数
time   平均 CPU 时间
```

并解释：

```latex
The \texttt{count} value refers to the best objective value obtained among the
compared methods rather than a proven optimum, with ties counted for all tied
methods.
```

## 7. MIP 结果描述技巧

不要笼统写：

```latex
TPIG outperforms MIP.
```

因为 MIP 可能只是限时 incumbent，而且在部分小规模实例上 MIP 可能更好。

更稳妥的写法是：

```latex
The MIP model provides competitive reference solutions on the smallest
instances, but requires substantially longer computational time. For larger
small-scale groups, the MIP model reaches the time limit, whereas TPIG obtains
feasible solutions within a short runtime.
```

如果 TPIG 在部分组不如 MIP，应客观表述：

```latex
TPIG provides objective values comparable to the time-limited MIP reference in
most groups.
```

## 8. 实验结果写作技巧

实验结果不要过度解释，不要写主观推测，例如：

```latex
TPIG will become more beneficial when the problem scale increases.
```

更好的衔接是：

```latex
These results motivate the subsequent evaluation on larger and more complex
benchmark settings.
```

如果后面大规模结果确实证明 TPIG 更好，可以在大规模实验部分写：

```latex
In contrast to the small-scale results, TPIG becomes more effective as the
number of jobs and machine-calendar interactions increase.
```

## 9. Future Research 写作技巧

Future research 不宜列得过散。相近方向可以合并。

原来的两个方向：

```text
capacity-management settings
hard no-tardiness / service-level constraints
```

可以合并为：

```text
more realistic operational and service-level requirements
```

推荐写法：

```latex
One direction is to incorporate more realistic operational and service-level
requirements. This includes capacity-management settings involving flexible
work calendars, reserved capacity, and multi-resource coordination. It may also
include stronger protection mechanisms for high-priority jobs, such as hard
no-tardiness constraints or service-level constraints.
```

## 10. 英文表达技巧

避免中文式句首 `Because`。

不推荐：

```latex
Because public benchmarks do not cover the integrated setting studied in this
paper, synthetic instances are generated for the computational experiments.
```

推荐：

```latex
The integrated setting studied in this paper is not covered by existing public
benchmarks. Therefore, synthetic instances are generated for the computational
experiments.
```

也可以写成：

```latex
As existing public benchmarks do not cover the integrated setting studied in
this paper, synthetic instances are generated for the computational experiments.
```

但拆成两句通常更自然。

避免同一词组在相邻句中重复，例如：

```text
machine-unavailability periods
```

可根据语境替换为：

```text
machine calendars
availability restrictions
available machine intervals
planned downtime intervals
```

但不要为了替换而造成概念不清。

## 11. 摘要中方法表述技巧

算法缩写可以直接放在方法名称后，不必写 `denoted as`。

推荐写法：

```latex
To address this gap, we formulate an integer programming model and develop a
two-phase iterated greedy (TPIG) framework.
```

比下面的写法更简洁：

```latex
To address this gap, we formulate an integer programming model and develop a
two-phase iterated greedy framework, denoted as TPIG.
```

## 12. 小规模 MIP 对比段落写作技巧

小规模 MIP 对比段落建议遵循：

```text
实验设置 → 表格指标说明 → MIP 限时性质 → 结果观察 → 方法定位
```

推荐表述：

```latex
The MIP model is further used as a reference method on small-scale instances,
where exact optimization remains computationally meaningful under a restricted
time budget. The comparison is conducted on instances with \(g=5\) stages,
\(n \in \{10,20\}\) jobs, and high-priority-job ratios
\(\rho \in \{0.1,0.2,0.3\}\). The MIP model is solved with a 600-second time
limit, whereas TPIG is run under the computational settings used in the
corresponding small-scale experiments.
```

## 14. 文献定位技巧

对于本文问题，应明确说明 ASC 或其他期刊中已有相近研究，但没有完全同构的问题组合。

可用表述：

```latex
Recent studies in Applied Soft Computing have addressed hybrid or flexible
flow-shop scheduling with tardiness-related objectives, multi-objective
optimization, maintenance-related constraints, and soft-computing
metaheuristics. However, these studies usually cover only part of the setting
considered in this paper. In particular, no closely matching ASC study was found
that jointly considers due-window-based total weighted earliness and tardiness,
high-priority jobs sharing due windows, planned machine-unavailability periods,
and non-preemptive operation feasibility in an HFSP environment.
```


# 01 Introduction：引言怎么设计

Introduction 的任务不是详细综述文献，而是回答四个问题：

```text
这个问题为什么重要？
本文研究的具体调度问题是什么？
现有研究哪里不足？
本文做了什么贡献？
```

建议写成 5–6 个自然段。

---

## 第 1 段：应用背景与现实动机

这一段从制造环境出发，说明为什么需要研究这个问题。
核心不是先讲算法，而是先讲现实问题。
这一段的功能是：**说明问题来自现实生产，而不是人为拼接约束。**
---
## 第 2 段：明确本文研究的问题

第二段要把问题定义出来。这里应出现你的核心组合：

但是不要堆得太长。可以分两句写：```

这一段的重点是：**读者读完后知道你的问题是什么。**

## 第 3 段：解释为什么这个问题难

这一段不要泛泛写 “NP-hard and difficult”，而要解释你的问题为什么比普通 HFSP 更复杂。

可以从三个耦合关系写：

这一段的功能是：**说明本文问题不是简单叠加约束，而是有新的可行性和目标耦合。**

---

## 第 4 段：概括已有研究与不足

Introduction 里不要展开太多文献。这里只需要概括已有研究做到了什么、没做到什么。详细文献放到 Related Work。

这一段不要出现太多 citation，也不要写成长文献综述。它的功能是：**引出 research gap。**

## 第 5 段：本文方法

这里说明你做了什么，包括 MIP 和 TPIG。

# 02 Related Work：相关工作怎么设计

Related Work 的任务是证明：

```text
你知道这个领域已有研究；
你能把已有研究准确分类；
你能说明本文和已有研究的区别；
你的 gap 是自然形成的，不是强行造出来的。
```

你的 Related Work 建议保持 5 个小节：

```latex
\section{Related Work}

\subsection{Hybrid flow shop scheduling and due-date-related objectives}

\subsection{Due-window-based total weighted earliness and tardiness scheduling}

\subsection{Priority differentiation and high-priority job scheduling}

\subsection{Machine unavailability and non-preemptive operations}

\subsection{Research gaps and positioning of this study}
```

## 2.1 Hybrid flow shop scheduling and due-date-related objectives

这一节回答：

```text
HFSP 是什么？
HFSP 常见目标是什么？
due-date-related objectives 在 HFSP 中处于什么位置？
```

写作脉络：

第一段介绍 HFSP 基础和重要性：

```latex
The hybrid flow shop scheduling problem is an important extension of the
classical flow shop, where jobs visit the same sequence of stages and each stage
may contain one or more parallel machines.
```

第二段说明 HFSP 研究中 makespan 很常见，但 due-date-related objectives 也很重要：

```latex
While makespan has been the dominant objective in much of the HFSP literature,
delivery-oriented criteria such as total tardiness, weighted tardiness, maximum
tardiness, and earliness--tardiness penalties have received increasing
attention.
```

第三段过渡到你的研究：

```latex
These studies show that HFSP research has moved beyond makespan minimization.
However, due-window-based weighted earliness--tardiness objectives remain less
frequently studied, especially when combined with priority differentiation and
machine-calendar constraints.
```

这一节的功能是：**说明你的车间类型和交付目标是合理的研究方向。**

---

## 2.2 Due-window-based total weighted earliness and tardiness scheduling

这一节是你 Related Work 的核心，因为你的目标函数是：

```text
due-window-based total weighted earliness and tardiness
```

这一节建议按发展脉络写：

```text
due date ET → due window ET → weighted ET → HFSP due-window TWET
```

第一段讲 due-date ET：

```latex
Earliness--tardiness scheduling was initially developed around due-date-based
models, where completing a job either before or after its due date incurs a
penalty.
```

第二段讲 due windows：

```latex
Due-window scheduling extends the due-date concept by defining an acceptable
completion interval. Jobs completed before the window incur earliness penalties,
whereas jobs completed after the window incur tardiness penalties.
```

第三段强调 due-window TWET 的难点：

```latex
Unlike tardiness-only objectives, earliness--tardiness objectives are
non-regular with respect to completion times. Therefore, inserting idle time may
improve the objective value, which makes schedule construction more difficult.
```

第四段讲 HFSP 中已有 due-window TWET 研究，但指出它们没有你的组合：

```latex
In HFSP environments, due-window-based weighted earliness--tardiness studies
have considered important extensions such as sequence-dependent setup times or
blocking constraints. However, high-priority jobs sharing due windows and
planned machine-unavailability periods have not been sufficiently integrated
into this objective framework.
```

这一节的功能是：**支撑你的目标函数选择，并说明它与普通 tardiness 不同。**

---

## 2.3 Priority differentiation and high-priority job scheduling

这一节的逻辑要特别注意。不要直接从 “weights” 跳到 “shared due windows”。中间要加一层：

```text
job-level priority → order/task-level priority → shared due windows
```

推荐写作脉络：

第一段讲传统 priority differentiation：

```latex
Priority differentiation is commonly represented through job-level weights,
where larger weights indicate greater importance or higher delay penalties.
```

第二段指出 job-level weights 的局限：

```latex
Such a treatment regards priority as an individual-job attribute. In practice,
however, high-priority jobs may originate from the same urgent order, customer
project, or coordinated delivery task.
```

第三段自然引出 shared due windows：

```latex
In such cases, multiple high-priority jobs may need to be protected jointly and
completed within a common delivery window. This motivates the use of shared due
windows for high-priority jobs, rather than treating each job independently.
```

第四段指出 gap：

```latex
Although priority differentiation, rush orders, and customer-order scheduling
have been studied in different contexts, their integration with due-window-based
weighted earliness--tardiness HFSP remains limited.
```

这一节的功能是：**解释为什么 high-priority jobs 不只是权重不同，还可能共享 due windows。**

---

## 2.4 Machine unavailability and non-preemptive operations

这一节应分成两个概念：

```text
machine unavailability
non-preemptive / nonresumable operations
```

第一段讲 machine unavailability：

```latex
Machine unavailability has been widely studied in scheduling, where machines
may be unavailable during known intervals due to maintenance, shift calendars,
breaks, or other planned activities.
```

第二段讲它在 flow shop / HFSP 中的影响：

```latex
In flow-shop-type environments, machine-unavailability periods restrict the
available processing intervals at each stage and may significantly affect both
machine assignment and operation start times.
```

第三段讲 non-preemptive operations：

```latex
Another important issue is whether an operation can be interrupted by an
unavailable interval and resumed later. Under non-preemptive processing, an
operation must be processed continuously and entirely within an available
machine interval.
```

第四段讲你的问题为什么更复杂：

```latex
For the present problem, machine unavailability and non-preemptive operations
are structurally coupled. A feasible decoder must not only select a machine and
a start time, but also ensure that the entire operation fits into an available
slot without crossing a downtime interval.
```

这一节的功能是：**为你的 feasibility-preserving decoding 做铺垫。**

## 2.5 Research gaps and positioning of this study

这一节不要再重新引用大量文献。它应该承接前文并总结 gap。

推荐结构：

```latex
\subsection{Research gaps and positioning of this study}

Table~\ref{tab:related-work-gap-summary} summarizes representative related
studies from the perspective of due-window modeling, weighted
earliness--tardiness objectives, priority differentiation, machine
unavailability, and non-preemptive processing across downtime periods.

\input{02_related_work/Summary of research gaps}

The preceding subsections show that the main components of the present problem
have been studied in different scheduling contexts. However, these features
have mainly been considered in partial combinations rather than within a unified
HFSP framework. In particular, three aspects remain insufficiently integrated.

First, existing studies usually represent priority differentiation through
job-level weights and thus treat job importance as an individual-job attribute.
However, high-priority jobs may also arise from urgent orders or coordinated
delivery tasks, where multiple jobs need to be protected jointly through shared
due windows.

Second, planned machine-unavailability periods have rarely been incorporated
into due-window-based weighted earliness--tardiness HFSP models, although such
unavailable intervals are common in practical production calendars.

Third, when machine unavailability is combined with non-preemptive operations,
feasibility and objective evaluation depend not only on machine calendars, but
also on whether each operation can be fully processed within an available
interval.

Accordingly, this paper studies an integrated HFSP that combines
high-priority jobs, shared due windows, planned machine-unavailability periods,
and non-preemptive operations within a unified weighted
earliness--tardiness framework.
```

这一节的功能是：**明确告诉审稿人：本文不是单纯换目标或换算法，而是集成了以前没有充分组合的几个现实特征。**

# 03 Problem Formulation：问题建模写什么

这一章建议包括：

```text
3.1 Problem description
3.2 Assumptions
3.3 Notation
3.4 Objective function
3.5 Constraints
3.6 Model remarks
```

重点内容包括：

```text
作业集合、阶段集合、机器集合；
普通作业与高优先级作业；
due windows 的定义；
machine-unavailability periods 的定义；
non-preemptive operation assumption；
目标函数 TWET；
机器选择、工序顺序、机器不重叠、不可用区间、完工时间、提前/延误变量。
```

这一章要让读者明确：

```text
什么是 feasible schedule；
目标函数如何计算；
MIP 变量和约束是否能完整表达问题。
```

结尾可以加一句：

```latex
The proposed model is mainly used to formally define the problem and to provide
a small-scale reference for computational comparison, since the problem becomes
computationally difficult as the number of jobs and machine-calendar
interactions increase.
```

这样可以自然衔接后面 MIP 小规模对比。

# 06 Conclusion：结论写什么

Conclusion 建议 3 段即可。

第一段总结本文研究了什么：

```latex
This paper studied an integrated hybrid flow shop scheduling problem with
high-priority jobs, due windows, planned machine-unavailability periods, and
non-preemptive operations under a total weighted earliness--tardiness objective.
```

第二段总结方法和结果：

```latex
An integer programming model was formulated, and a two-phase iterated greedy
framework was developed. Computational results showed that the proposed method
provides competitive solution quality within short computational times and is
effective for large-scale benchmark instances.
```

第三段写 future research：

```latex
Future research may extend the proposed framework by incorporating more
realistic operational and service-level requirements, such as flexible work
calendars, reserved capacity, multi-resource coordination, hard no-tardiness
constraints, or service-level constraints. Another direction is to consider
uncertainty and dynamic events, such as random machine failures, processing-time
disturbances, and urgent order arrivals.
```

# 01 和 02 的核心区别

这点很重要。

**Introduction 是讲故事：**

```text
现实中为什么有这个问题？
本文研究什么？
现有研究缺什么？
本文做了什么？
```

**Related Work 是做分类和定位：**

```text
已有研究分别做了哪些方向？
每个方向和本文有什么关系？
它们为什么还没有覆盖本文的问题？
```

不要在 Introduction 中写太多细节文献；也不要在 Related Work 中反复讲现实背景。
