# Writing Specification

This directory addresses difficult **How** problems that remain after the Structure Specification has already defined **Where + What**.

A Writing Specification should exist only when the content is easy to write poorly even after its structural responsibility is known.

Examples:
- narrowing an Introduction instead of writing generic background;
- synthesizing literature instead of stacking papers;
- translating code into scientific method language;
- explaining experimental patterns instead of reading table cells;
- converting visual evidence into bounded scientific narrative.

Do not use this directory to repeat the chapter structure. Simple, low-reasoning text such as a paper-organization paragraph belongs in `templates/`.

Files:
- `abstract.md`
- `introduction.md`
- `related-work.md`
- `problem-and-model.md`
- `solution-method.md`
- `experiments.md`
- `conclusion.md`
- `visual-evidence-to-narrative.md`
- `code-to-method-narrative.md`
