# 计算实验

从验证问题和源结果设计本章：

```text
声明或研究问题
-> 数据集/实例角色
-> 对比方法与公平预算
-> 指标与分析单位
-> 统计或分析方法
-> 结果、不确定性、例外与边界
```

排程启发式或元启发式论文默认使用[第5章固定标题模板](../../templates/chapter5-computational-experiments-template.md)，除非目标期刊或现有稿件已经规定其他结构。这是本skill对实验职责的组织方式，不表示已发表论文使用完全相同的编号。参数和组件证据通常放在完整算法比较之前，用来解释最终配置为何成立。删除无证据的条件模块后再统一编号。

## 章节开头

**Guide：**验证目的 -> 研究问题 -> 数据角色 -> 实现与计算环境 -> 证据结构

说明实验验证什么，区分标准基准、生成/修改数据和真实案例数据。报告足以解释和复现实验预算的信息：语言/运行时、硬件、相关时的操作系统或容器、求解器/版本/接口、线程、时间或评价预算、停止容差、随机种子、重复次数，以及预处理/训练是否计时。不得用常见配置补写未知信息。

## 5.1 `Experimental Setup`

按以下顺序写：

1. 研究问题和各实例组的实验职责；
2. 数据来源、问题结构、规模、生成/修改规则，以及校准集与测试集的划分；
3. 实现与计算环境；
4. 对比方法的选择理由和配置来源；
5. 一致的停止/计算预算、种子、重复运行和失败运行处理；
6. 指标公式、单位、优劣方向、分母、参考值状态和分析单位。

用“基准实例及其用途”表和“实现与评价协议”表集中呈现设置。不得让同一数据在未披露的情况下兼作调参与最终测试。若算法使用不同语言、机器或直接引用已发表结果，没有可靠归一化时不得把运行时间写成可直接比较。

## 5.2 `Parameter Calibration`（条件）

参数若预先固定或继承，删除本节，在5.1说明数值及来源。确实校准时，报告因素、范围/水平、校准实例、实验设计、响应值、聚合方式、交互处理、选择规则和最终设置。条件允许时校准集与最终测试集分离，并披露任何重叠。

可选图表：

- `Parameter calibration design and selected settings for [algorithm name].`
- `Main effects of [parameters] on [calibration response].`

使用真实设计名称；非正交设计不得写成Orthogonal。解释最终设置为何可能不同于单次观测最优组合。小规模校准集不能证明普遍稳健。

## 5.3 `Component Analysis`（有组件贡献声明时）

使用组件真实名称。保持其余协议不变，移除、替换或改变一个可解释组件；交互作用重要时可采用并披露析因设计。比较解质量、不确定性、运行时间和受益条件。组件无法隔离时应缩小因果措辞并说明混杂因素。

```text
声明的组件
-> 受控变体
-> 相同数据与预算
-> 质量、波动与代价
-> 设计能够支持的机制解释
-> 适用范围与例外
```

典型标题：`Comparison of [component name] strategies under [budget and instance scope].`

## 5.4 `Comparison with Benchmark Algorithms`

用一张主表呈现完整算法的目标值、波动、时间、失败、并列，以及按规模/场景的表现。基准方法必须有技术选择理由、可信实现/配置来源和公平预算。只有在已核实方法地位时，才改用`Comparison with State-of-the-Art Methods`。

正文不能只宣布胜者；还要说明主要结果、实质性并列、反转、分组效应、失败和质量—时间权衡。最好结果次数必须有参考值和并列规则。

适用时把小规模精确/参考比较放在本节，报告可行解、最好界、相对gap公式、最优证明状态、运行时间和限时状态。区分精确最优、best-known、已发表参考值和本次实验最好值，并核对最小化/最大化的界方向。

## 5.5 `Statistical Analysis`（条件）

根据实验单位、配对关系、分布、方法数量和多重比较结构选择推断方法，不能因为某个检验更容易显著而选择它。保留逐次运行数据，但在跨实例结论中，不能把同一实例的多次运行当成独立问题实例。

报告假设、分析单位、配对方式、统计量、样本量、适用时的原始/校正p值，以及效应量或置信区间。区分统计显著性和实际重要性。Friedman+Holm或配对Wilcoxon只是在设计和假设匹配时可用的示例。

## 5.6 `Search Behavior and Computational Efficiency`（条件）

使用相同墙钟时间或有依据的工作量单位。说明实例/曲线选择与聚合规则，不得只挑有利曲线。讨论初始质量、前后期改进、停滞、跨运行不确定性、可扩展性及质量—时间权衡。工作量不可比或没有搜索行为声明时，不强制收敛图。

典型图表：

- `Time-normalized convergence profiles of the compared algorithms on [scope].`
- `Runtime and scalability of [algorithm] by instance size.`

## 5.7 `Sensitivity and Robustness Analysis`（条件）

在受控设计下改变模型参数、算法参数、约束紧度、不确定性、问题规模、时间预算或数据扰动。本节回答稳定性和边界问题，不能重复5.2的参数选择。会改变解释的非单调、无明显变化和不利响应都应报告。

## 可选 `Real-World Case Study`

只有存在真实案例数据、来源/匿名化说明、现实业务基准及离线评估—部署边界时，才在讨论前插入本节。在完整分支中，该节编号为5.8，`Discussion`顺延为5.9。构造基准实例不是实际案例。

**Guide：**业务环境 -> 数据来源 -> 参数化 -> 现实基准 -> 结果与权衡 -> 实际意义 -> 局限

## 5.8 `Discussion`

用前述证据逐项回答研究问题，把组件证据与完整算法表现连接起来，协调统计意义和实际意义，解释例外和计算代价，并限定结论范围。本节不得引入新的结果或无证据机制。

## 结果描述顺序

每个保留图表按以下顺序讨论：

```text
图表回答的问题
-> 数据、对比对象和指标
-> 带不确定性的主要结果
-> 重要例外、反转或失败
-> 有设计支持的解释或权衡
-> 有边界的结论
```

不要逐单元格复述，也不要从非受控比较中推断因果。

## 完整性与真实性检查

每个结论都应定位到具体结果图表和覆盖的实例/运行总体。回查源结果文件中的优劣方向、分母、四舍五入、并列规则、缺失/失败运行及指标/参考值定义；核对论文参数与生成结果时实际使用的参数一致。不得虚构或静默删除不利结果。
