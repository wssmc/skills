# 求解方法

## 章节开头

**Guide：**方法设计动机 -> 总体框架 -> 编码与解码 -> 初始化 -> 核心方法及组件 -> 伪代码 -> 理论或复杂度分析

说明为何不能直接求解、利用了什么问题结构、提出的方法属于哪一类。

## 4.1 总体方法框架

**Guide：**求解困难 -> 方法性质 -> 设计思想 -> 主要模块 -> 模块接口 -> 输出

明确方法是精确、分解、近似、启发式、元启发式、混合式或学习辅助方法。说明输入、模块、信息流、当前解/最好解更新、停止条件和输出。

默认框架图：`Figure X. Overall framework of the proposed [method name].`

来源示例：`Figure X. Overall framework of the proposed two-phase solution approach.`

## 4.2 编码与解码

**Guide：**决策信息 -> 编码 -> 解码 -> 可行性 -> 评价

说明哪些决策直接编码、哪些在解码时确定，如何保持/修复可行性，以及评价值如何对应模型目标。

无显式编码时，标题改为“解的表示与方案生成”。

## 4.3 初始化

**Guide：**作用 -> 候选规则 -> 初始方案生成 -> 评价 -> 默认初始化

初始化不构成独立方法时并入4.4。

## 4.4 核心求解方法及其组成

先用一段说明完整方法，再按实际名称设置组件小节。每个组件说明：目的和目标缺陷、步骤/公式/规则、输入输出与可行性、前后模块衔接、必要伪代码。禁止“组件A/B”。

完整伪代码包含输入输出、初始化、主循环、组件调用、候选接受、当前解/最好解更新和停止条件。

来源算法标题形式包括：Phase-I backward decoding、Non-final-stage left-shift compaction、Phase-II forward decoding、Destruction、Reconstruction、Local search、Acceptance criterion。

## 4.5 理论性质或复杂度分析

精确/分解方法可讨论正确性、界和有限收敛；近似方法只在有证明时给出保证；启发式可讨论可行性保持、终止性和时间复杂度。定义规模参数，分析解码与主要组件，给出单次迭代和总体复杂度。无正式依据不得声称收敛、最优或近似保证。
