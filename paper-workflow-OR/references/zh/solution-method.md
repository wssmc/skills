# 求解方法

## 章节开头与方法分支

**Guide：**方法设计动机 -> 总体框架 -> 编码与解码 -> 初始化 -> 核心方法及组件 -> 伪代码 -> 理论或复杂度分析

说明计算或理论需求、利用的问题结构和方法类别。只有在复杂性、规模、精确/参考实验或明确需求支持时，才能声称“无法直接求解”。

按方法类型选择内容：

- **精确/分解方法：**模型变换、界、主问题/子问题或定价/分离逻辑、有效性、收敛/终止，以及复现所需实现细节。
- **启发式/元启发式：**解表示/构造、可行性处理、搜索组件、接受/更新逻辑、终止条件和随机实验协议。
- **近似算法：**算法与已证明的保证及其假设。
- **学习辅助方法：**预测/学习目标、训练数据划分、特征、数据泄漏控制、与优化模块的接口、可行性保护和非学习基线。
- **混合/数学启发式：**各组件负责的决策、接口信息和预算分配。

## 4.1 总体方法框架

**Guide：**求解困难 -> 方法性质 -> 设计思想 -> 主要模块 -> 模块接口 -> 输出

明确方法是精确、分解、近似、启发式、元启发式、混合式或学习辅助方法。说明输入、模块、信息流、当前解/最好解更新、停止条件和输出。

只有模块接口、迭代流程或信息交换无法通过简洁正文和伪代码清楚表达时才使用框架图。可用：`Figure X. Overall framework of the proposed [method name].`

来源示例：`Figure X. Overall framework of the proposed two-phase solution approach.`

## 4.2 解表示或数学分解

**Guide：**决策信息 -> 编码 -> 解码 -> 可行性 -> 评价

对基于表示的方法，说明哪些决策直接编码、哪些在解码时确定，如何保持/修复可行性，以及评价值如何对应模型目标。

无显式编码时，使用“方案构造”“主问题与子问题”“定价问题”“割生成”或其他真实功能标题，不要把编码/解码结构强加给精确、分解或直接数学过程。

## 4.3 初始化

**Guide：**作用 -> 候选规则 -> 初始方案生成 -> 评价 -> 选定初始化方式

只有初始化具有实质作用、影响性能或为复现所必需时才单列，否则并入核心方法或实现设置。

## 4.4 核心求解方法及其组成

先用一段说明完整方法，再按实际名称设置组件小节。每个组件说明：目的和目标缺陷、步骤/公式/规则、输入输出与可行性、前后模块衔接，以及为复现所需的伪代码、方程或精确协议。禁止“组件A/B”。

完整伪代码包含实际存在的输入输出、初始化、迭代/分解循环、组件调用、候选接受、当前解/最好解或界更新和停止条件。有实现时核对符号、改进方向、并列处理、可行性逻辑和终止条件。

来源算法标题形式包括：Phase-I backward decoding、Non-final-stage left-shift compaction、Phase-II forward decoding、Destruction、Reconstruction、Local search、Acceptance criterion。

## 4.5 理论性质或复杂度分析

精确/分解方法可讨论正确性、界和有限收敛；近似方法只在有证明时给出保证；启发式可讨论可行性保持、终止性和时间复杂度。定义规模参数并说明复杂度是最坏、摊还还是经验意义；只分析真正主导的操作，不能用忽略求解器调用或可变迭代次数的装饰性Big-O。无正式依据不得声称收敛、最优或近似保证。
