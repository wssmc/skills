# 防御性学术写作审计

## 适用范围

当用户要求检查或改写以下表达时读取本参考：防御性写作、审稿人导向表达、免责声明堆叠、结果辩解、未做实验的辩护、过度自我限定、审稿回复式论文表述，或希望使 OR 论文更加直接、证据导向和克制。

本参考审计的是论文的表达姿态和证据边界，不替代问题建模、数学正确性、算法机制、实验设计或统计结论审计。它也不是简单的 hedge-word 删除器，不得为了语气直接而删除必要的科学限定或增强原有主张。

## 核心写作原则

优先采用：

```text
技术主张 -> 支持证据 -> 简洁且必要的边界
```

而不是：

```text
预想审稿质疑 -> 免责声明 -> 辩护理由 -> 弱化主张 -> 再次免责声明
```

技术事实应先出现。只有当限定条件会改变模型有效性、可行域解释、结果含义、统计解释、可复现性或结论强度时，才保留该限定。

## 防御性表达类型

逐句识别下列模式；不要只按关键词机械判定。

| 编号 | 类型 | OR 论文中的典型表现 | 处理方向 |
|---|---|---|---|
| D1 | 审稿人预辩解 | “为避免误解”“审稿人可能认为” | 直接陈述技术事实 |
| D2 | 重复性否认 | 反复说明“本文不声称……” | 保留一次必要范围，其余删除 |
| D3 | 限定语堆叠 | 一个主张前后连续出现多个 although/only/may 等限定 | 保留最强且有证据的表述 |
| D4 | 结果辩解 | 先解释为什么结果较弱，再报告结果 | 先报告结果；只有有证据时解释 |
| D5 | 缺失实验辩护 | 为未做的基线、消融或敏感性分析主动辩护 | 若影响解释，作为一次限制说明 |
| D6 | “公平性”自我辩护 | “为了公平比较，我们……” | 直接说明实际控制的变量和协议 |
| D7 | 范围标签重复 | preliminary、limited、indicative 等反复出现 | 仅在技术上必要时保留 |
| D8 | 法律式免责声明 | 长串“不得理解为……” | 改为简洁的正向范围陈述 |
| D9 | 无关防御性披露 | 报告不影响有效性或解释的过程性失败 | 删除或移至补充材料 |
| D10 | 形容词补偿 | 用 robust、promising、effective 等替代度量结果 | 改为数值、协议或具体性质 |
| D11 | 自动化总结句 | “这些结果共同证明……”但没有新增推论 | 删除或改为具体推论 |
| D12 | 证据边界过度提示 | 每个结果后都重复“仅在本实验范围内” | 将重要范围集中说明一次 |
| D13 | 绝对化防御 | “任何方法都无法……”“这不可能……” | 改为有条件、有证据的陈述 |
| D14 | 重新命名式创新 | 通过改名或反复声明“不只是 X”来制造创新 | 直接说明实际技术差异 |

## 必要限定与防御性限定

对疑似防御性句子依次检查：

1. 删除该句是否会使读者误解模型、证据或结论？
2. 该句是否给出了可验证的条件、关系、假设、误差或适用范围？
3. 该句的主要作用是否只是预先回应想象中的审稿意见？
4. 是否可以改写为“在所评价设置下观察到……”等正向表述？
5. 同一限定是否已经在其他位置出现？

分类为：

- `NECESSARY_CAVEAT`：改变科学解释，必须保留；
- `DEFENSIVE`：主要用于自我保护，应删除或改写；
- `MIXED`：同时包含技术边界和防御性措辞，应拆分；
- `CLEAN`：直接、必要且证据一致。

## OR/调度论文专用判断

- **问题与模型：**保留会改变可行域、目标函数、调度假设或模型适用范围的限定。
- **算法方法：**直接说明编码、解码、搜索、接受和更新机制；不要用“本文并不声称重新发明标准方法”来代替贡献层次说明。
- **贡献表述：**区分标准组件和实际技术增量。标准 NEH、SA 或普通邻域应描述其功能；创新应写成具体的权重更新、信息反馈或决策规则。
- **计算结果：**先报告目标值、相对差距、运行时间或统计结果，再解释原因。没有诊断证据时，不为弱结果提供推测性解释。
- **比较协议：**描述实例、预算、种子、重复次数和评价指标；不要用“公平”“合理”“充分”作为未经定义的自我评价。
- **理论与证据：**`optimal`、`convergent`、`robust`、`generalizable`、`significant` 等词必须有相应证明、实验、统计检验或明确条件支持。
- **范围说明：**将会影响读者解释的限制放在最相关的位置，并尽量只说明一次；不要在贡献、方法、结果和结论中重复同一免责声明。

## 审计流程

### Pass 1 — Detection

逐句标记 D1–D14，并记录其所在章节、段落或句子位置。

### Pass 2 — Necessity classification

为每个候选句分配 `NECESSARY_CAVEAT`、`DEFENSIVE`、`MIXED` 或 `CLEAN`。

### Pass 3 — Reviewer-perception analysis

仅对 `DEFENSIVE` 和 `MIXED` 项，用一句话说明其可能造成的阅读感受，例如主张被延迟、作者在预先辩护、结果解释超过证据或贡献表述不够直接。

### Pass 4 — Evidence-preserving rewrite

按以下顺序改写：

1. 将技术事实移到句首；
2. 用已有证据限定主张强度；
3. 删除只服务于预先辩护的语句；
4. 保留一个必要的科学边界；
5. 不用宣传性形容词补偿删除后的语气；
6. 不改变数学含义、数值、单位、条件、符号或引用。

### Pass 5 — Paper-level check

当获得完整论文或足够大的章节范围时，检查：

- 摘要和贡献列表中的预先辩解；
- 方法章节中对标准组件的重复自我定位；
- 结果章节中的弱结果辩解和“公平性”声明；
- 结论中的自我削弱或重复免责声明；
- 同一限制在多个章节中的重复出现；
- 形容词、绝对化表达和自动化总结句是否有证据支持。

## 审计输出

显式要求审计时，使用以下字段组织结果：

| Location | Original | Type | Severity | Necessary caveat? | Why it feels defensive | Likely reviewer reaction | Recommended action | Rewrite |
|---|---|---|---|---|---|---|---|---|

严重性可分为：

- `Critical`：明显的 rebuttal 式、法律式或强烈自我辩护；
- `Major`：重复限定、结果辩解、缺失实验辩护或宣传性补偿；
- `Minor`：局部但可感知的防御性措辞。

完整论文审计可以另外给出 0–10 的防御性写作评分，但评分不能替代逐项证据和改写建议；单个段落或普通润色任务不强制输出评分。

## 工作模式边界

- 普通 drafting：执行轻量检查，只删除高置信度的防御性表达，不输出完整审计表。
- polishing/translation：在不增强主张的前提下，改为直接、证据导向的表达。
- explicit defensive-writing audit：执行完整五阶段审计并输出逐项结果。
- scientific or mathematical audit：防御性写作检查不能替代模型、证明、算法或实验有效性审查。
