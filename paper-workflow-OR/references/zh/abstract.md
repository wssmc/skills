# 摘要

摘要应是一篇可独立阅读的“微型论文”，按连贯逻辑回答五类问题：

```text
研究背景 -> 研究问题 -> 方法 -> 主要结果 -> 含义
```

目标期刊采用结构式摘要时，可按其小标题调整顺序，但不能因为套用句式而遗漏研究问题、方法、结果或含义。

## 功能结构

### 1. 背景与问题

用一到两句把研究领域收束到具体缺口或决策问题。避免长篇行业背景、宏观意义堆叠和未经核实的“尚无研究”。

### 2. 研究目标

明确本文研究、求解、证明或检验什么。研究对象、核心决策/变量或问题名称应清楚出现。

### 3. 方法

概括构成贡献的模型、理论、算法、数据或实验设计。只保留定义研究能力和验证方式的信息，不展开参数和实现细节。

### 4. 主要结果

报告最能回答研究问题的结果。条件允许时给出比较对象、差异幅度、覆盖范围、统计不确定性或最优性/证明状态。所有数字必须出现在正文或其源结果中，不能用“结果表明方法有效”替代证据。

### 5. 含义

说明结果在理论、方法或实践层面意味着什么，并保持在已验证场景和假设范围内。不要重新介绍方法或增加正文没有支持的新结论。

## 证据就绪分支

- **已完成研究：**报告主要结果、比较/参考、适用范围，以及必要的不确定性或证明状态。
- **方案、协议或进行中研究：**不得把计划实验写成已完成结果；按文档类型说明目标与拟采用方法，不虚构预期发现。
- **起草时缺少结果证据：**只写已有支持的句子或给出摘要结构计划，并把需要补充的结果槽位列在摘要之外。

不要机械复制填空式模板，应让句法服从论文真实的因果和证据关系。

## 不同论文类型的重心

- **模型—算法型：**决策问题 -> 数学模型/算法 -> 数据与比较设计 -> 性能或性质结果 -> 方法价值与边界。
- **理论/精确方法型：**开放问题 -> 假设/模型 -> 理论或算法工具 -> 定理/界/计算结果 -> 理论含义。
- **应用型：**决策场景 -> 研究问题 -> 数据/模型/方法 -> 运行或计算结果 -> 实践含义与适用条件。
- **综述型：**范围与筛选方法 -> 分类框架 -> 主要趋势/缺口 -> 研究议程。

## 写作与核验

- 除非期刊要求结构式摘要，通常写成一个段落。
- 不放引文、图表、复杂公式；缩写首次出现时定义。
- 不使用无证据的`novel`、`significant`、`effective`等裸评价词。
- 不把引言和结论的句子拼接成摘要。
- 遵循期刊字数限制；背景从简，方法适量，结果通常占最大信息量，但不按固定比例凑字数。
- 完成后把每个数字和声明回查到正文、图表及源结果文件。
