# 信息收集与路径选择

## 按交付结果选择路径

先判断主要任务属于：结构设计、正文起草、结构修改、润色/翻译、审计或文献/证据工作，同时记录交付物与范围。不要把一句话润色扩展成整篇论文模板，不要在只读审计中直接改文件，也不要为局部文本请求擅自启动大范围文献综述。

## 就绪门槛

先检查用户已提供的文件和上下文，只追问会阻断当前交付的信息：

| 交付物 | 通常所需的最少信息 |
|---|---|
| 结构/段落计划 | 论文类型、核心问题、预期贡献、证据状态、已知期刊约束 |
| 可投稿正文 | 要陈述的事实、可支持的声明、相关符号/结果/引文、语言与段落功能 |
| 模型/方法说明 | 实际公式或算法设计、符号/接口、性质声明及证明或证据状态 |
| 计算实验正文 | 数据来源、实验设计、基准与预算、指标、逐次或汇总结果、必要环境信息 |
| 润色/翻译 | 原文和目标语言；仅在确实影响修改时才需要期刊风格 |
| 审计 | 待检查材料、审计范围，以及核验声明所需的源文件/结果 |
| LaTeX直接修改 | 项目根目录/主文件、修改范围、模板、结果真值源、可用编译命令 |

不会改变技术含义或事实声明时，可以采用有边界的假设，并在论文正文之外说明。规划任务应显式标记缺口，不必因每个未知项停下来。

## 集中式提问

确需提问时，一次只发送下列相关子集，不要把整张清单强制交给用户：

1. **期刊与格式：**目标期刊/文章类型、模板和实质性限制。
2. **问题：**基础运筹问题、决策、目标、资源、约束、不确定性，以及居于主线时的应用角色。
3. **模型/理论：**模型类型、公式完整性、符号、参数构造和证明状态。
4. **方法：**方法类别、适用时的表示/编码、真实组件、接口、伪代码和性质声明。
5. **证据：**数据、基准、预算、重复运行、统计设计、消融、案例/敏感性证据和实现环境。
6. **交付：**语言、交付物、编辑范围，以及需要规划、正文、直接修改还是仅报告问题。

## 论文类型分支

- **应用或决策驱动型：**现实决策场景、决策对象和资源限制是主线。
- **问题或方法驱动型：**新变体、新约束、新目标或算法改进是主线，现实决策抽象较弱。
- **模型或理论驱动型：**建模、分解、精确算法或理论分析是主要贡献。

## 文献综述路径

选择一种：

- 问题/应用 -> 模型/决策描述 -> 算法/求解方法 -> 研究缺口。
- 基础问题 -> 具体研究专题 -> 综合缺口。
- 混合路径：问题/应用 -> 具体专题 -> 模型 -> 算法 -> 综合缺口。

## 证据状态

内部区分：用户已提供、外部已核实、可直接推导、计划但未执行、缺失、禁止推断。只有前三类可写成已完成事实。

来源冲突时不要继续传播数字或结论：指出冲突；数值声明优先回到实际数据、代码或结果文件；无法安全确定真值源时再向用户确认。
