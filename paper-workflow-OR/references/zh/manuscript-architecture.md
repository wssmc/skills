# 论文整体结构

## 运筹优化论文主线

```text
研究背景
-> 运筹决策或优化问题
-> 研究缺口与技术困难
-> 数学模型
-> 求解方法
-> 计算证据
-> 理论/实践意义与边界
```

## 备用正文结构

1. 引言
2. 文献综述/相关工作
3. 问题描述与数学模型
4. 求解方法
5. 计算实验
6. 结论与未来研究

这是“模型—算法—计算”型论文的备用结构，不是必须套用的外壳。期刊、论文类型或论证逻辑需要时可以合并、拆分或改名。例如，理论型论文可合并问题与模型，应用型论文可把案例背景和计算验证分开。

### 结论的功能

按论文证据覆盖下列功能，不强制固定段落数或条目数：

1. 把研究问题与模型/方法贡献重新连接起来。
2. 只概括主要理论或计算发现，并在有依据时报告最关键的效应量或差异幅度。
3. 在证据边界内解释理论或实践含义。
4. 说明重要适用边界，并把有价值的未来研究与造成边界的机制对应起来。

结论中不要引入新实验或新引文，不要逐项重复结果，也不要把本应在前文呈现的不利证据藏到结论里。目标期刊有明确结构要求时，以期刊模板为准。

## 章节规划表达

```text
Guide：要素 -> 要素 -> 要素
段1：本段功能和内容。
段2：本段功能和内容。
```

不再用①②等序号表达章节内容。

默认提供章节层级蓝图，说明每节写什么，以及需要哪些公式、算法、表格和图形。只有用户明确要求逐段说明时，才展开其指定小节，并保证每段具体到可以据此起草。

规划类交付默认使用可直接阅读的聊天正文或Markdown。只有明确要求LaTeX或直接修改源码时才输出原始TeX；只有用户要求时才创建Word或PDF。

## 小标题控制

- 只有承担独立论证、方法或证据功能的内容才设置小标题。
- 不承担独立功能的说明内容合并为段落；读者必须导航不同声明或过程时再拆分。
- 三级标题仅用于实际算法组件、证据模块或独立文献主题，不为凑数量而设置。
- 长证明、低层实现、完整参数表和补充实验按期刊规则移至附录。

## 证据模块选择

按图表或模块所回答的问题来选择，常见候选包括：文献矩阵（并列编码更能揭示缺口时）、示例实例（问题或可行性逻辑不直观时）、符号表（符号量较大时）、框架图（模块接口或信息流难以靠简洁文字/伪代码解释时）、参数校准证据（参数确由实验选择时），以及与精确性、统计优势、收敛、组件作用、案例有效性或稳健性声明相匹配的证据。

删除装饰性或重复项。每个主要图表都应服务于贡献、研究问题、可复现性需求或可预见的审稿风险。
