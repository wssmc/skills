# LaTeX项目直接修改

## 检查顺序

主.tex与模板 -> input/include文件 -> bib与样式 -> 图和caption/label -> 结果表文件 -> algorithm环境 -> 代码/日志/输出 -> 期刊前后置内容。

## 修改前

识别编译方式；可用时先检查版本控制状态或其他变更基线，保留用户无关修改；条件允许先编译或读取当前日志，避免把已有错误归因于本次修改。检查期刊对标题、摘要、highlights、作者声明、附录和caption的要求；建立标签、引用、图、表、公式、算法、文献和包含文件清单；明确待修改文件/章节，以及公式、算法和结果数值的真值源。

## 修改规则

- 模板优先于通用六章结构。
- 保持数学含义和用户结果。
- 尽量保持label稳定；改变后更新全部引用。
- 通常在caption后放label，除非模板另有要求。
- 结果可从生成文件读取时，不在多个位置手工复制。
- 删除提交稿中的计划说明和占位内容。
- 标题和caption使用实际算法/组件名称。
- 除非明确在范围内或确有错误，保留自定义宏、文献键、作者注释和格式命令。
- 命令、公式或引文键可能受影响时，优先窄范围编辑，不做全局替换。
- 不得用猜测数据重新生成图表；应定位生成脚本/数据源，否则明确说明未验证再生成过程。

## 验证

检查编译与相关警告（可用时和修改前基线比较）、未定义引用/文献、重复label、缺失文件、表格/公式溢出、图表顺序、过时数字和caption、文献缺失，以及摘要—贡献—结果—结论一致性；最后检查实际diff是否出现范围扩张、公式/数值意外变化或无关格式噪声。

优先使用项目已有构建方式，除非用户要求，不为让本地编译通过而擅自引入新工具链。无法编译时报告尝试过的具体命令、依赖或错误，不能声称成功。
