# 通用项目结构总结（新项目模板）

> 本文档是面向新项目生成的通用结构规范，基于 HFSP-MO-NLPC 工程实践经验提炼。
> 结合 `scripts/核心脚本结构.md` 的脚本设计，形成完整的「数据 → 求解 → 输出 → 分析 → 论文」全链路模板。

---

## 0. 设计原则

1. **可复现**：确定性种子、确定性输出、结果可从 txt 序列复现并校验
2. **可扩展**：算法注册制，新增算法只需注册到 `run_baselines.py`
3. **分层清晰**：数据层、求解层、评估层、输出层、分析层各自独立
4. **面向论文**：所有实验设计围绕论文需求（对比、消融、DOE、统计检验）
5. **禁止随意生成脚本**：优先复用核心脚本（single / bench / batch / analysis）
6. **加速评估**：增量评估 + 计算缓存（FIFO 队列，大小限制 500）避免重复解码，控制内存占用
7. **改进必须消融**：每一次算法组件改进（新增邻域、接受准则、初始化策略等）都必须进行消融实验，量化改进程度（正或负），并撰写完整的消融实验记录文档
8. **组件测试配置**：消融实验取每个规模算例的**第一个**作为测试算例，使用固定种子，repeat=3
9. **输出隔离**：所有实验输出仅限项目内 `outputs/` 目录，禁止输出到项目外路径（如 `/tmp`）
10. **执行安全**：预估耗时超过 1 小时的任务必须后台运行（`nohup`/`&`），并提供 `tail -f` 日志跟踪命令

## 3. 数据层（`data/`）

> 不同问题会要求不同的算例（作业数、阶段数、机器数、约束类型等各异），本节主要描述目录结构规范，具体参数由问题决定。

### 3.1 目录结构

```text
data/
├── generate.py             # 数据生成入口
├── loader.py               # 数据读取（load_instance）
├── demo/                   # 展示用算例
│   └── demo_01_n_m/        # 命名: demo_0x_n_m
│       ├── *.txt           # 算例数据文件
│       ├── index.json      # 文件索引
│       └── *.png / *.pdf   # 可视化图（demo 专属）
├── small/                  # 小规模基准算例
│   └── inst_xxx_n_m_yy/    # 命名: inst_xxx_n_m_yy
├── large/                  # 大规模基准算例
│   └── inst_xxx_n_m_yy/
└── batch_seeds/            # 统一种子文件
    ├── small/
    │   ├── seed_table.json # 种子主表
    │   └── round{r}.json   # 每轮种子映射
    └── large/
        ├── seed_table.json
        └── round{r}.json
```

### 3.2 数据生成 — `data/generate.py`

数据生成入口放在 `data/` 目录下。**不在算例生成时传入 seed 参数，也不写入 `index.json`**。种子管理统一由测试阶段的 `data/batch_seeds/` 种子文件控制。

生成逻辑要点：
- 定义 demo / small / large 三种规模的参数组合（作业数、阶段数、机器数等由问题决定）
- 每个规模组合生成指定数量的算例
- 算例命名：demo 用 `demo_0x_n_m`，正式算例用 `inst_xxx_n_m_yy`
- `index.json` 仅记录文件索引和问题元信息，不记录 seed

### 3.3 数据读取 — `data/loader.py`

数据读取函数 `load_instance(dir) -> Instance` 放在 `data/` 目录下（当前项目在 `src/io/txt_loader.py`，新模板迁移至此）。

### 3.4 单算例文件格式

每个算例目录包含的数据文件**由问题决定**，通常包括工时矩阵、机器配置、前序关系等。`index.json` 串联所有文件的索引。具体文件类型和格式由问题定义，详见 `docs/` 下的数据格式文档。

### 3.5 demo 算例的特殊性

demo 算例**承担展示问题的任务**，有别于正式测试：

1. **额外生成可视化**：前序网络图、操作关系图等（具体由问题决定）
2. **输出更丰富**：运行 demo 时输出甘特图 + 排程 JSON + 详细日志，用于直观展示问题结构
3. **不参与批量统计**：demo 结果不进入 ARPD 计算
4. **规模小**：便于人工验证

### 3.6 统一种子管理

测试阶段读取统一的种子文件，与算例生成解耦：

- `data/batch_seeds/{scale}/seed_table.json` — 种子主表（算例名 → seed）
- `data/batch_seeds/{scale}/round{r}.json` — 每轮种子映射
- 种子源：`random.Random(20260616 + sum(ord(c) for c in scale))`
- 单次运行无指定 seed 时默认 `secrets.randbits(32)`

## 4. 源代码层（`src/`）

### 4.1 `src/core/` — 领域模型

核心数据结构，被所有模块共享：

```python
@dataclass
class Instance:          # 算例数据（工时、机器、前序关系等）
@dataclass
class Schedule:          # 排程结果（操作列表、目标值）
@dataclass
class Result:            # 完整结果（方法、状态、目标值、运行时间、排程）
@dataclass
class Operation:         # 单个操作（作业、阶段、机器、开始/结束时间）
@dataclass
class PrecedenceArc:     # 前序弧
```

### 4.2 `src/math_models/` — MIP / CP 建模（Gurobi）

> 从 `src/solvers/mip/` 迁移，**不再放在 `solvers/` 下**，直接作为 `src/` 下的一级目录。

- **MIP（混合整数规划）**：用 Gurobi 实现，建模文件 `gurobi_model.py`
- **CP（约束规划）**：如需实现，放同一目录下
- **下界计算**：`lower_bound.py`（快速下界 + 精确下界）
- **结果校核**：MIP 求解后必须调用 `check_feasibility(instance, schedule)` 验证约束满足

**Gurobi 测试要求**：
- 输出 **LB（下界）** 和 **规定时间内的最优可行解**
- 默认时限 **3600 秒**
- 输出 `result.json`（含 status, objective, LB, gap, runtime, violations）+ `schedule.csv` + `gantt.png`

### 4.3 `src/metaheuristics/` — 元启发式算法

> 目录名不用 `algorithms`，因为研究范围涵盖精确算法、启发式、元启发式、强化学习、LLM 辅助设计等多种方法。
> 当前主要研究元启发式，因此命名为 `metaheuristics/`。

#### 目录结构

```text
src/metaheuristics/
├── initial/              # 初始化方法
│   ├── dispatching.py    # 调度规则初始化（SPT, LPT 等）
│   ├── neh.py            # NEH 启发式
│   ├── random_init.py    # 随机初始化
│   └── topological.py    # 拓扑排序初始化
├── encoding/             # 编码方案（多套）
│   ├── sequence_encoding.py        # 置换序列编码
│   ├── machine_order_encoding.py   # 机器顺序编码
│   └── ...                         # 其它编码（按需扩展）
├── decoding/             # 解码方案（多套）+ 评估校验
│   ├── list_decoder.py             # 列表解码
│   ├── block_decoder.py            # 分块解码
│   ├── incremental_eval.py         # 增量评估（加速解码方法）
│   ├── eval_cache.py               # 计算缓存（FIFO 队列，限制大小 500，加速重复评估）
│   ├── feasibility_checker.py      # 可行性检查（校验排程是否满足约束）
│   ├── metrics.py                  # 目标值计算（Cmax 等）
│   └── result_reproducer.py        # 从 txt 序列复现目标值并校验
├── neighborhood/         # 邻域算子（详见 4.3.1）
├── baselines/            # 论文正式对比算法（文献复现）
├── sa/                   # 模拟退火 (SA)
├── ma/                   # 模因算法 (MA)
├── ig/                   # 迭代贪心 (IG)
├── ga/                   # 遗传算法 (GA)
└── ts/                   # 禁忌搜索 (TS)
```

> **evaluation 与 decoding 的关系**：可行性检查、目标值计算、结果复现都依赖解码逻辑——feasibility_checker 验证排程的正确性，result_reproducer 用解码器重新解码 txt 中的序列。因此 evaluation 相关文件**放在 `decoding/` 目录下**，与解码器紧密耦合。

#### `neighborhood/` — 邻域算子

邻域算子是元启发式算法的核心组件，集中管理所有邻域移动操作，供 SA / IG / MA / GA / TS 等算法共享调用。

```text
src/metaheuristics/neighborhood/
├── operators.py              # 邻域算子定义与实现
├── critical_path.py          # 关键路径相关邻域
├── frameworks.py             # 邻域选择框架（VNS / ALNS / 随机均匀等）
└── structure_context.py      # 结构上下文缓存（NEST/LOT 分组、前序映射等）
```

针对当前 HFSP-MO-NLPC 问题实现的邻域算子：

| 类别 | 算子 | 说明 |
|------|------|------|
| **Insert** | `NEST_INSERT` | 在 NEST 作业序列中执行插入移动 |
| | `LOT_INSERT` | 在 LOT 作业序列中执行插入移动 |
| | `GLOBAL_INSERT` | 在全局作业序列中执行插入移动 |
| **Swap** | `NEST_SWAP` | 在 NEST 作业序列中执行交换移动 |
| | `LOT_SWAP` | 在 LOT 作业序列中执行交换移动 |
| | `GLOBAL_SWAP` | 在全局作业序列中执行交换移动 |
| **Block** | `NEST_BLOCK_MOVE` | NEST 作业块移动 |
| | `GLOBAL_REVERSE` | 全局序列片段逆序 |
| **Critical Path** | `CRITICAL_PATH_PRED_FORWARD` | 关键路径上前驱作业前移 |
| | `CRITICAL_PATH_RELOCATE` | 关键路径上作业重定位 |
| | `CRITICAL_PATH_RELOCATE_2` | 关键路径上双作业重定位 |
| **Release Window** | `RELEASE_WINDOW_LOT_REORDER` | 释放窗口内 LOT 重排序 |

**邻域选择框架**（`frameworks.py`）：

| 框架 | 说明 |
|------|------|
| `VnsState` | 变邻域搜索：按固定顺序 N1→NK 遍历，接受最优改进时回 N1 |
| `UniformRandomState` | 均匀随机选择：所有算子等概率，用于无偏数据采集 |
| `AlnsState` | 自适应大邻域搜索：根据算子历史表现动态调整权重 |

#### `decoding/` 详细说明

| 文件 | 职责 |
|------|------|
| `list_decoder.py` 等 | 各套解码器，将编码转化为可行排程并计算目标值 |
| `incremental_eval.py` | 增量评估，属于加速解码方法，在邻域搜索中避免全量重解码 |
| `eval_cache.py` | 计算缓存，属于加速方法。用 FIFO 队列保存已计算的编码→目标值映射，**队列大小限制 500**，避免内存过大。在评估时优先查缓存命中，未命中再解码计算 |
| `feasibility_checker.py` | `check_feasibility(instance, schedule) -> violations`，校验排程是否满足所有约束 |
| `metrics.py` | 目标值计算（Cmax 等） |
| `result_reproducer.py` | 从 txt 输出的序列复现目标值，并校验约束条件 |

**结果复现**：算法输出的 txt 中包含最优解序列，通过 `result_reproducer.py` 重新解码并计算目标值，复现结果必须与原始结果一致，并校验是否满足约束条件。

#### `baselines/` — 论文对比算法

存放从文献复现的对比算法。这些算法是论文中用于与本文提出算法进行对比的基准，每个对比算法一个文件，注册到 `run_baselines.py` 统一调度。

对于新问题，默认实现以下 **5 个基础元启发式**：

| 算法 | 目录 | 说明 |
|------|------|------|
| SA | `sa/` | 模拟退火 |
| MA | `ma/` | 模因算法 |
| IG | `ig/` | 迭代贪心 |
| GA | `ga/` | 遗传算法 |
| TS | `ts/` | 禁忌搜索 |

#### 编码解码

根据问题特征，可能需要实现多套编码解码方案：
- **置换序列编码**：全作业的一个排列
- **每阶段序列编码**：每个阶段一个作业排列
- **每机器序列编码**：每台机器一个作业排列
- 其它编码：按需扩展

每套编码必须有对应的解码器，解码器负责将编码转化为可行排程并计算目标值。

> **解码器接口规范**：相似解码器（如多个 seq_machine 解码器）的输入和输出要控制一致；不同编码类型之间（seq vs seq_machine）**不强制一致**，因为输入数据结构不同。所有解码器输出统一为 Schedule 对象。

### 4.3.1 算法打印规范

算法运行过程中必须按以下规范打印日志：

- 每行日志以 `[算法名]` 前缀
- **启动信息**：`[{algo}] Start | instance={inst} | time_limit={N}s | seed={seed}`
- **进度信息**：`[{algo}] iter={iter} | time={t}s | best={obj}`
- **结束信息**：`[{algo}] Done | best={obj} | runtime={t}s`
- verbose 分级：0 静默 / 1 仅启动结束 / 2 打印进度
- 禁止在循环内频繁打印（至少间隔 1 秒或 N 次迭代）

### 4.3.2 收敛曲线数据与绘制规范

**trace.csv 数据格式**：
```csv
iteration,time,objective
0,0.00,12.50
1,0.01,11.80
```

**绘制规范**：横轴迭代/时间，纵轴目标值；多算法对比附图例；200 DPI；宽 10 英寸 × 高 6 英寸；网格 alpha=0.3。

## 6. 算法命名、分支与注册规范

### 6.1 算法命名层级

算法命名遵循 **`{父算法}_{变体}`** 模式，子算法必须带父算法名作为前缀，分为三个层级：

| 层级 | 命名示例 | 说明 |
|------|---------|------|
| **basic** | `sa_basic`, `ig_basic`, `ma_basic` | 最基础实现，是 study 的起点 |
| **study** | `sa_basic_study`, `ig_basic_study`, `ma_basic_study` | 在 basic 基础上完善的研究版本，是分支的基础 |
| **branch** | `sa_basic_study_conditioned`, `ig_basic_study_tour_inc`, `sa_basic_study_qlig` | 基于 study 的改进分支，用独立文件固化开关选择 |

### 6.2 basic → study → branch 演进关系

```text
sa_basic (基础 SA)
  └── sa_basic_study (研究版 SA，完善邻域、冷却、接受准则)
        ├── sa_basic_study_conditioned (条件化邻域分支)
        ├── sa_basic_study_qlig (Q-Learning 引导分支)
        ├── sa_basic_study_split4 (四序列分支)
        └── ... (更多分支)
```

- **basic**：最小可运行实现，验证基本框架正确性
- **study**：在 basic 基础上完善各组件，作为后续分支的统一基础
- **branch**：基于 study，通过开关组合不同策略（邻域、初始化、接受准则等），**每个分支用一个独立文件固化开关选择**

### 6.3 分支管理规范

> **核心原则**：分支的开关选择固化在分支自己的文件中，**不在 `run_baselines.py` 中设置开关**。

1. **study 文件**提供可配置的开关参数（如邻域类型、初始化方式、接受准则等）
2. **branch 文件**继承 study 的框架，在文件内部固化特定的开关组合：
   ```python
   # sa_conditioned.py 示例
   def solve_sa_basic_study_conditioned(instance, time_limit, seed, **kwargs):
       # 固化开关选择，不从外部传入
       return solve_sa_basic_study(instance, time_limit, seed,
                             neighborhood="conditioned",
                             init_method="neh",
                             accept_criterion="metropolis",
                             **kwargs)
   ```
3. **branch 注册到 `run_baselines.py`**：与 basic/study 一样走 5 步注册流程，方便统一管理
4. **`run_baselines.py` 不设开关**：中枢只负责调度，不传递算法内部开关参数。各算法的开关由自己的文件管理

### 6.4 算法注册步骤（`run_baselines.py`）

所有算法（basic / study / branch / baselines）必须注册：

1. 在 `ALGO_XXX` 常量区添加算法标识
2. 在 `ALGO_INFO` 添加 `AlgoInfo(name, short_name, full_name, zh_name, comment)` 元数据
3. 在 `ALGO_DEFAULTS` 添加默认参数
4. 在 `solver_map` 添加 solver 函数映射
5. 在 `elif algo in (...)` 分支条件加入算法标识

### 6.5 组件改进消融实验规范

> **强制要求**：每一次算法组件改进（新增邻域算子、接受准则、初始化策略、解码加速等）都必须进行消融实验，量化改进程度（正或负），并撰写完整的消融实验记录文档。未经消融验证的改进不得纳入正式版本。

#### 6.5.1 改进命名

每个改进组件必须命名，命名规则参考 `src/metaheuristics/ig/IG算法变体对比表.md`：

| 命名要素 | 说明 | 示例 |
|---------|------|------|
| **组件名** | 英文短语，描述改进核心 | `Dynamic d Destruction`、`Tournament Acceptance`、`Elite Archive` |
| **消融变体名** | `{算法}_{关闭组件}` | `ig_tour_inc_no_hamming`、`ig_tour_inc_core6` |
| **组件编号** | 按引入顺序编号 | `#1 Dynamic d`、`#8 Stagnation Detection` |

变体命名规则：
- `_{关闭组件名}`：关闭特定组件（如 `_no_hamming`）
- `_coreN`：只保留前 N 个组件（如 `_core6` = 组件 1-6）
- 每个消融变体注册到 `run_baselines.py`，走 6.4 注册流程

#### 6.5.2 测试配置

消融实验**不使用全部算例**，固定配置如下：

| 配置项 | 规定 | 说明 |
|--------|------|------|
| **测试算例** | 每个规模的**第一个**算例 | 如 small 取 `inst_051_10_5_01`，large 取 `inst_171_50_5_01` |
| **种子** | 固定种子 | 从 `data/batch_seeds/` 读取，或直接指定（如 seed=1,2,3） |
| **重复次数** | repeat=3 | 每个算例 × 每个种子运行 3 次 |
| **时间限制** | `N_jobs * M_stages * factor` | factor 与正式实验一致（默认 0.05） |

此配置已固化为 `scripts/ablation/quick_test_config.py`，作为所有小实验（消融、DOE、参数扫描）的默认算例数据来源，避免每次手动指定算例和种子。

### 7.1 架构总览

```
sh_single_instance.sh  ─┐  (单算例 · 单算法)
sh_bench_instance.sh   ─┼──> run_baselines.py ──> src/metaheuristics/*

```

### 7.2 核心脚本

#### `run_baselines.py` — 中央调度枢纽

**职责**：注册全部算法，解析算例目录，`ProcessPoolExecutor` 并行调度，统一写产物。

**输出（每个 算例 × 算法）**：

```
{out}/{instance}/{algo}_result.json      # Result(method, status, makespan, runtime, extra{best_seq, seed})
{out}/{instance}/{algo}_schedule.json    # 完整排程 (operations 列表)
{out}/{instance}/{algo}_trace.csv        # 迭代收敛 (iteration, time, objective)
{out}/{instance}/{algo}_gantt.png        # 甘特图
{out}/convergence.json                   # 汇总收敛数据
```

txt 模式额外产出：`{txt_out}/{algo}.txt`（保存算法返回的 **best_seq**，不从 schedule 反推）

#### `sh_single_instance.sh` — 单算例 · 单算法

**关键**：single 必须输出 `schedule.json` 和 `gantt.png`。

```bash
bash scripts/sh_single_instance.sh --inst <算例名|路径> --algo <算法名> [--time N] [--seed N] [--verbose 1]
```

**输出目录**：

```
outputs/single_{INST_NAME}_{ALGO}/
  {INST_NAME}/{algo}_result.json
  {INST_NAME}/{algo}_schedule.json
  {INST_NAME}/{algo}_trace.csv
  {INST_NAME}/{algo}_gantt.png
```

stdout 打印：`Cmax / Runtime / Status / Seed / Sequence / ScheduleJson 路径`

#### `sh_bench_instance.sh` — 单算例 · 多算法对比

```bash
bash scripts/sh_bench_instance.sh [算例路径|N_M_K|N_M] [算法1 算法2 ...]
```

**输出目录**：

```
outputs/bench_{INST_NAME}/
  {INST_NAME}/{algo}_result.json
  {INST_NAME}/{algo}_schedule.json
  {INST_NAME}/{algo}_trace.csv
  {INST_NAME}/{algo}_gantt.png
  {INST_NAME}_convergence.png            # 收敛曲线
```

#### `sh_batch_instances_algorithms.sh` — 全量批量 · 多轮

```bash
bash scripts/sh_batch_instances_algorithms.sh [small|large|all] [time_factor]
```

**输出目录**：

```
data/batch_seeds/{scale}/seed_table.json           # 种子主表
data/batch_seeds/{scale}/round{r}.json             # 每轮种子映射
outputs/batch/{batch_name}/round{r}/{scale}/       # 每轮运行产物
outputs/batch/{batch_name}/txt/{scale}/{algo}.txt  # 汇总 txt
```

**固定模式**：
- 7 轮循环，已有 `round{r}/` 数据则跳过（断点续跑）
- 种子源：`random.Random(20260616 + sum(ord(c) for c in scale))`
- 时间公式：`time = N_jobs * M_stages * factor`，factor 默认 `0.05`（单）/ `0.1`（批量）
- 并行：`ProcessPoolExecutor` + `--workers`，大规模 `W=2`，小规模 `W=4`

#### `sh_analysis.sh` — 通用结果分析

```bash
bash scripts/sh_analysis.sh <结果目录> [--standard auto|none|xlsx] [--profile auto] [--no-plots]
```

自适应目录，生成 xlsx + ARPD 图。

## 12. 实验设计体系

### 12.1 对比实验（batch）

- 多算法 × 多算例 × 多轮（默认 7 轮）
- 指标：ARPD（平均相对百分比偏差）、最优解数量、运行时间
- 输出：汇总 txt → `sh_analysis.sh` → xlsx + ARPD 图

### 12.2 消融实验（ablation）

- **组件级消融**：每次算法改进必须消融（详见 6.5 节），取每规模第一个算例，固定种子，repeat=3
- 初始化方法对比（随机 vs NEH vs 调度规则）
- 邻域算子对比（交换、插入、逆序等）
- 算法核心组件的开关测试（如 SA 的接受准则、IG 的破坏修复策略）
- 编码方案对比
- 消融记录文档含：命名、机制、参数、结果表、结论、脚本附录、双链

### 12.3 参数校核（DOE）

- 因子筛选：正交实验设计
- 参数调优：响应面方法
- 验证：最优参数组合的确认实验

### 12.4 统计检验（statistics）

- Friedman 检验：多算法整体差异显著性
- Wilcoxon 秩和检验：两两算法对比
- 多重比较校正：Holm / Hochberg 步降程序
- 可视化：临界差图（Critical Difference Diagram）

### 12.5 MIP 基准

- 小规模算例精确求解（3600s 时限）
- 输出 LB 和最优可行解
- 用于计算启发式算法的 Gap
- 结果必须经过可行性校核

## 13. 固定模式总结（迁移到新项目）

| 要素 | 固定模式 |
|------|----------|
| **数据层** | `load_instance(dir) -> Instance`；算例目录含标准 txt 文件集 + `index.json` |
| **数据生成** | `data/generate.py`，不在算例生成时传 seed，不写入 index.json |
| **数据读取** | `data/loader.py`，统一 `load_instance` 接口 |
| **种子管理** | 测试阶段读取统一种子文件 `data/batch_seeds/`，与算例生成解耦 |
| **求解层** | 每个算法签名: `solve_xxx(instance, time_limit, seed, **kwargs) -> (Schedule, trace_list, best_seq)` |
| **评估层** | `check_feasibility(instance, schedule) -> violations`，放在 `decoding/` 下 |
| **计算缓存** | `decoding/eval_cache.py`，FIFO 队列保存编码→目标值映射，**队列大小限制 500**，评估时优先查缓存 |
| **输出层** | 固定四件套: `result.json` / `schedule.json|csv` / `trace.csv` / `gantt.png` |
| **txt 序列** | 保存 **best_seq**（算法返回的最优编码序列），不从 schedule 反推 |
| **结果复现** | 从 txt 读取 best_seq → 解码 → 计算目标值 → 校验约束 |
| **三层脚本** | `sh_single` (单×单) → `sh_bench` (单×多) → `sh_batch` (全×多轮)；共享 `run_baselines.py` |
| **MIP 独立** | `mip/run_gurobi_mip.py` 独立入口，不走 `run_baselines.py`；输出 LB + 最优解；3600s 时限；结果校核 |
| **时间公式** | `time = N_jobs * M_stages * factor`，factor 默认 `0.05`（单）/ `0.1`（批量） |
| **并行** | `ProcessPoolExecutor` + `--workers`，大规模 `W=2`，小规模 `W=4` |
| **断点续跑** | batch 脚本检测 `round{r}/` 目录非空则跳过该轮 |
| **文档命名** | `docs/` 下文件前缀加日期 `YYYY-M-D` |
| **算法命名** | basic → basic_study → basic_study_xxx 三级；**子算法带父算法前缀**；分支用独立文件固化开关 |
| **算法注册** | 必须注册到 `run_baselines.py`（5 步注册流程）；开关不在中枢设置 |
| **消融实验** | 每次改进必须消融（快速验证目的）；每规模取第一个算例，固定种子，repeat=3；原始结果存 `outputs/ablation/{algo}/{name}/raw/` |
| **默认算法** | 新问题默认实现 SA, MA, IG, GA, TS 五个基础元启发式 |
| **邻域算子** | `metaheuristics/neighborhood/` 集中管理，含 Insert / Swap / Block / Critical Path 等多类算子 |
| **实验体系** | 对比(batch) + 消融(ablation) + DOE + 统计检验 + MIP 基准 |
| **论文** | `latex/` 含期刊模板 + 项目论文工作目录 |
| **项目记忆** | `AGENTS.md` 作为项目约定持久化记录 |
